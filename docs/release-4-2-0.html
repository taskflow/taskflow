System Requirements

To use Taskflow v4.2.0, you need a compiler that supports C++20:

  • GNU C++ Compiler at least v11.0 with -std=c++20
  • Clang C++ Compiler at least v12.0 with -std=c++20
  • Microsoft Visual Studio at least v19.29 (VS 2019) with /std:c++20
  • Apple Clang (Xcode) at least v13.0 with -std=c++20
  • NVIDIA CUDA Toolkit and Compiler (nvcc) at least v12.0 with host compiler supporting C++20
  • Intel oneAPI DPC++ Compiler at least v2022.0 with -std=c++20
Note
If your project does not support C++20, please use Taskflow v3.11.0, which can be downloaded here.

New Features

Taskflow Core

  • added two tf::Taskflow::emplace overloads for module tasks
    • tf::Taskflow::emplace(tf::GraphLike) equivalent to tf::Taskflow::composed_of
    • tf::Taskflow::emplace(tf::Graph&&) equivalent to tf::Taskflow::adopt
  • added task priority support via tf::Task::priority (credit to #784)
    • must be explicitly enabled through -DTF_ENABLE_TASK_PRIORITY
  • added the support for ND-index-range-based reduce
    • tf::Taskflow::reduce_by_index
  • refactored the core with several new concepts to enhance type safety and readability
    • tf::InputIteratorLike to check if a type is a stateful iterator
    • tf::UnaryOperationLike to check if a unary operation is valid
    • tf::BinaryOperationLike to check if a binary operation is valid
    • tf::UnaryTransformLike to check if a unary transform is valid
    • tf::BinaryTransformLike to check if a binary transform is valid
  • fixed missing tf::TaskParamsLike concept usage in async tasking
  • replaced generic template type in dependent async tasks with std::input_iterator
  • improved ND parallel-for scheduling with a local recursive partition
